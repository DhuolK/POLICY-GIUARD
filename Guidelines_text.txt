4.0. PROJECT DOCUMENT
Upon the supervisors’ approval of the detailed project proposal and implementation, students should proceed to prepare their project documentation under the supervisor’s guidance; the document should:
(a) Use appropriate tense to clearly convey the timing and progression of activities.
(b) Have a minimum of 25 and maximum of 50 pages of the main document.
(c) Use the standard paper size (typically A4 or letter size) for the document.
(d) Set margins uniformly to normal to ensure adequate white space.
(e)  Use a readable font Times New Roman for the document
(f)  Font size should be 12 points for the main text.
(g) Use bold or italics sparingly for emphasis.

3.4 System analysis and design (SAD)
System analysis and design (SAD) is a critical phase in the development of the project, It involves understanding and specifying in detail what a system should do and how the components of the system should be implemented and interact with each other. Here’s an overview of how to approach system analysis and design in a project:
3.4.1 System Analysis
System Analysis" typically refers to the structured process of examining and defining the requirements and functionalities of a system. This phase is crucial as it lays the foundation for designing and developing a solution that meets the stakeholders' needs effectively.
Requirements Gathering
* Interviews: Conduct interviews with stakeholders to understand their needs and expectations.
* Surveys and Questionnaires: Use these tools to collect data from a larger audience.
* Observation: Observe current systems in use to identify pain points and areas for improvement.
* Document Analysis: Review existing documentation, manuals, and reports to gather requirements.
Requirements Analysis
* Functional Requirements: Define what the system should do (e.g., processes, data handling, user interactions).
* Non-Functional Requirements: Define how the system should perform (e.g., performance, security, usability).
* Use Cases: Develop use cases to describe interactions between users and the system.
* User Stories: Write user stories to capture specific functionalities from the end-user perspective.
 Feasibility Study
* Technical Feasibility: Assess whether the technology needed for the project is available and practical.
* Economic Feasibility: Evaluate the cost-effectiveness of the project.
* Operational Feasibility: Determine if the proposed system will operate within the current organizational environment.
System Modeling
* Data Flow Diagrams (DFDs): Visualize the flow of information within the system.
* Entity-Relationship Diagrams (ERDs): Model the data relationships within the system.
* Unified Modeling Language (UML): Use UML diagrams like class diagrams, sequence diagrams, and activity diagrams to model the system’s structure and behavior.
3.4.2 System Design
System Design section follows the system analysis phase and focuses on detailing how the system will be structured and implemented based on the requirements.
Architectural Design
* System Architecture: Define the overall architecture of the system, including hardware, software, and network components.
* Layered Architecture: Use layered design (e.g., presentation layer, business logic layer, data access layer) to organize the system.
Detailed Design
* Component Design: Break down the system into smaller components or modules and specify their interactions.
* Database Design: Design the database schema, including tables, relationships, indexes, and constraints.
* User Interface Design:
Outline the approach to designing the user interface (UI).
Include wireframes or mockups to illustrate the UI layout and user interactions.
* Algorithm Design (if applicable):
Detail any algorithms or computational methods that will be implemented in the system.
Provide pseudocode or flowcharts to explain the logic behind these algorithms
 Prototyping
* Low-Fidelity Prototypes: Create sketches or wireframes to represent the user interface and workflow.
* High-Fidelity Prototypes: Develop interactive prototypes to provide a more realistic user experience.
Design Specification
* Technical Specifications: Document the technical details of the system design, including hardware and software requirements.
* Design Documents: Create comprehensive design documents that include diagrams, descriptions, and explanations of the system’s components and their interactions.
 Review and Validation
* Design Review: Conduct design reviews with stakeholders to ensure the design meets the requirements.
* Validation: Validate the design against the requirements to ensure completeness and correctness.
